## HDMI 专项

`python script/test_hdmi_vendor.py` 默认检查正式原厂核，回执 build/hdmi_vendor_sim/result.json。`--direct` 检查历史直接核，不能代替正式路径。每个场景要求正向 PASS，运行时不得修改相关 RTL。

测试音、非对称立体声和真实 V4 的 BGM＋四 SFX 经 SD 仲裁／跨域桥／混音／原厂 HDMI／PHY 串行引脚恢复，并与独立 WAV 黄金逐样本对照。检查 TERC4、BCH、奇偶、IEC 状态、48kHz／24-bit、N6144／CTS25000、InfoFrame，13 种音频负例和 4 种媒体负例必须检出。

保留正常游戏尾链与校准叠层两条检查，另检查实际 HUD 和补偿 128；逐行像素、同步及完整帧结束都需正确，RGB 故意错一拍负例必须失败。DDC 只覆盖启动活动和无应答时继续输出，不包含会应答的真实显示器。本专项与图库／最终字幕组合测试互补，不是整个顶层的实板替身。

只有最终 RTL 稳定后重跑，并核对 source_hashes，才能将回执用于交付。仅在结尾生成哈希的旧运行，如果中途改过输入，不作为该输入版本的验证证据。

## 构建与配套

```powershell
python script/build_td_gui.py
python script/check_project.py
python script/check_deployment.py
python test/test_deployment.py
```

check_deployment 检查真实 staging、当前位流／构建回执以及原 V4 六图／24 轨镜像；不会刷新 staging 掩盖过期，也不访问设备。test_deployment 包含过期位流、GUI 登记／AutoExcluded、打开工程时禁止改写、素材及音频目录损坏等 15 项测试。登记测试包含实际报错的三个新增模块，并检查相对路径、综合开关和重复同步幂等性。已有工程的原生 RUN 直接读取持久 RTL 清单，不靠临时 `add_files` 补齐。以实际命令成功退出为准，构建失败时旧 bit 不能交付。

`python script/verify.py` 是 14 组完整回归入口。只有 run.json 全部通过并绑定当前输入快照，才能声称完整回归；分项 results.json 只是进度。

## 历史诊断

A/B 640×480 与 C 800×600 探针在用户自有屏上均未解决环绕，随后人工补偿版获用户确认正常。script/test_video_diagnostic.py、test_video_svga.py 和 test_video_board.ps1 保留用于追溯，不再作为当前游戏候选。数字像素模型只锁住已知循环移位现象，不能证明显示器故障根因。当前操作见 [板上说明](../doc/board-demo.md)。
