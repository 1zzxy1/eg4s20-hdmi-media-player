## 性能取舍

- 一帧 640×480×4 = 1228800 字节，双缓冲 2457600 字节，占 8MiB SDRAM 的 29.30%；保持完整 RGB888，低 8 位填零。
- 25MHz / (800×525) = 59.5238Hz。有效显示读带宽约 73.14MB/s，有效行内瞬时需求 100MB/s。
- SDRAM 40MHz×4 = 160MB/s 是理论峰值，实际有效值需扣除刷新、读写切换和 FIFO 开销。128 字突发与 512 字 FIFO 是初始配置，不能把峰值当作实测吞吐。
- SPI 12.5Mbit/s 理论 1.5625MB/s；单张 BMP 921654 字节，纯数据至少约 0.59s，实际还需命令和扇区等待。轮播等待当前装载结束，再计时约 1s，不承诺每秒精确切换。
- 原 125MHz SDRAM 与 100MHz 解析路径未满足时序。降低到 40MHz / 50MHz 后取得正余量，未用全域 false path 绕过 SDRAM 时序检查。
- 音频在像素域以 520/521 周期交替使能，平均精确 48kHz；1kHz 双声道方波，ACR N=6144、CTS=25000。48 个样本精确对应 25000 像素周期。
- 亮度采用饱和加减，状态条采用比较器，无 DSP 和额外帧缓存。

## 已修正的参考问题

1. AXIS TLAST 落在每行第 640 个有效像素，并验证两帧 SOF/数据对齐。
2. 首版把FIFO连接线扩大到10位，但原IP实际使用9位计数、有效深度511；这不是已证明的“修复截断”。扩展版改为显式9位计数补零，并加入真实FIFO回读验证。
3. 分别记忆源数据完成和内存完成，避免完成事件先后顺序造成死等。
4. 帧边界提交后回传确认，旧显示 bank 才可复用；read/write ACK 增加接收域同步。
5. 两个 PLL lock 共同控制复位，各域同步释放；补齐视频流水寄存器复位。
6. BMP 比较完整 32 位尺寸，限制 offset/size，像素只取 921600 字节，忽略尾随元数据。
7. 修正 include、重复模块选择、SD 未用写数据端口和 TD 6.2 ADC/SDC 语法。

## 尚未关闭的风险

- `PHY-7002`：TD 对 `u_sdram/sdram` 的中间 ECO 位置给出告警。工程未给 SDRAM 手工 LOC，最终路由无多驱动且 bitgen 成功；仍需上板内存测试，不能仅靠位流判定物理正确。
- `PHY-5079`：仅 `mem_shift -> u_sdram/u2_ram/SDRAM_CLK` 的一个封装时钟端点使用本地布线。脚本只接受这个具体路径，不豁免额外逻辑时钟；物理时钟质量仍需硬件验收。
- IP 内部还有未连接端口等警告，vendor 文件保持原样。尚未进行加密 IP 的端到端协议仿真。
- 当前 SDC 尚无完整 TF 卡板级 IO 延迟模型，HDMI 眼图和接收端兼容性未测。正 WNS 不等于全部外部接口时序已证明。
- 读取逻辑只支持扇区寻址的 SDHC 型卡；没有 CMD58 容量识别、完整 FAT 遍历、碎片文件、CRC 校验、热插拔恢复和有界重试。无卡可能一直等待，扫描不足四图时需扫到上限。
- 当前 FIFO 欠载/溢出未加入粘滞诊断；LED4 仅报告 HDMI 输入流 ready 违约。刷新竞争与长稳显示必须实测。
- 配置 Flash 固化、掉电重启、音视频、切换无撕裂和至少 60 分钟长稳测试未完成；本项目不是已验收的完赛作品。
