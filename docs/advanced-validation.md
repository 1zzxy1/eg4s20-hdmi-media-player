# 五项扩展：功能、软件证据与资源取舍

2026-10-09，HX4S20C / EG4S20BG256，TD 6.2.168116、Icarus Verilog、ModelSim SE-64 10.6e。五个方向集成在同一顶层，默认 `all`。是否裁减由用户决定；尚未进行实板验收。

## 功能与可操作范围

| 方向 | 已实现 | 操作/范围 |
|---|---|---|
| 图层与字幕 | 内置5×7字模、上电计时、滚动字幕、半透明文字面板 | SW3；MM:SS计时每100分钟回绕；字幕每两帧移动1像素 |
| 转场 | 16级淡出→全黑换bank→16级淡入；逐步显影 | KEY4长按≥1秒后松开切换FADE/WIPE；约0.6秒一次转场 |
| 缩放 | 加载侧最近邻，正确处理BMP行填充和跨扇区像素 | 正高度、24-bit BI_RGB，宽1..1920/高1..1440，拉伸至640×480 |
| 实时参数 | 饱和亮度、围绕128的对比度、参数OSD | SW1/2：0/+32/+64/−32；KEY4短按：100/50/150/200%；帧边界提交 |
| 音频可视化 | 实际PCM的64点波形、峰值条、双bank快照 | SW4；每帧发布完整采样窗；与HDMI音频使用同一PCM源 |

仍保留KEY2下一张、KEY3自动轮播。对比度先处理、再加亮度、饱和到0..255、再执行转场，最后叠加图层。图层和参数在帧内稳定。上电首图无需先淡出；只有新图写完且淡出全黑，显示端才确认切bank，确认前不能复用旧显示bank。

不把扩展方向的示例混为已实现：没有FFT、双线性插值、保持比例黑边、两图交叉混合或真正的平移转场。显影是对黑显示，不是两图混合。波形是64样本约1.33ms窗口，不是整帧连续采样史；时间戳不是RTC墙钟。课程参考/自写代码边界见 [code-provenance.md](code-provenance.md)。

## 验证与复现

统一入口：`python scripts/verify.py`。每个子步骤非零退出或缺少PASS回执都会使门禁失败。证据与当次源码SHA-256保存在 `build/verification/`，不进入Git。

| 验证层 | 实际覆盖 |
|---|---|
| 静态检查 | 顶层23个端口位均有唯一管脚，vendor来源哈希不变 |
| Icarus模块/链路 | 11项：音频/ACR、AXIS、commit、旧BMP/亮度回归、地址翻转、新转场、波形、按键/BCD、坏图自动跳过、真实FIFO/帧DMA/视频时序 |
| BMP黄金 | 23场景：多尺寸/奇数宽/极端尺寸/跨扇区；两张完整640×480输出；非法头/短扇区/中途失败/超时/严格模式；错误黄金像素必须使测试失败 |
| 视频黄金 | 9种配置×2完整帧=5529600像素；独立Python黄金逐RGB比较，检查SOF/TLAST和消隐；实际按键驱动所有对比度档位、显影模式，无强制内部寄存器 |
| 原厂SDRAM控制器 | ModelSim运行真实加密控制器，外接自建JEDEC功能器件模型；真实FIFO、三时钟域、帧翻转与完整回读，期间向另一bank并发写入58752字 |
| BMP→SDRAM组合链路 | 真实扇区缓存缩放器→真实FIFO背压→原厂加密控制器→器件模型→真实视频时序；640×480输出逐像素正确，并发写另一bank74752字 |
| 原厂HDMI核 | 真实加密HDMI核和TD RAM/FIFO模型，5帧数字仿真；2064623周期锁定、1091840个基础RGB像素成功解码、4031个PCM样本激励，锁定期间无AXIS背压/未知TMDS值 |
| TD | 全功能及七种对比配置完成综合/布局布线；最终位流生成受setup/hold门禁控制 |

`tb_loader_recovery` 的源文件在扫描后故意产生短扇区，要求自动跳到下一张有效图，累计完整307200个像素后才提交；不是只让解析器回到IDLE。源码错误恢复不会提交半帧。

已修正且有实验证据的关键问题：原参考DMA没有使用控制器busy/refresh，原厂控制器仿真会出现无效写；加入突发开始门控后通过。字幕33字符赋入32字符寄存器造成首字母截断，由黄金像素检测并修正。SD控制域增加BUFG，FIFO写入许可异步断言/同步释放，关闭了新布局中的负hold路径。

### 仿真边界

全部“通过”限于已列出的有限测试集，不是对任意输入和物理环境的数学证明。ModelSim确实使用原厂加密HDMI/SDRAM控制器；SDRAM阵列另用自建功能器件模型，不能冒充原厂阵列或速度等级时序签核。Icarus扇区模型没有覆盖SD SPI电气及所有卡兼容行为。HDMI测试没有完整音频接收器、数据岛ECC/校验码逐包判定、EDID矩阵或模拟PHY眼图。厂商模型的既有位宽/未连接端口警告保留在日志，没有隐藏成“零警告”。

`text`包括共用文字面板；`color`这一单项只测调色运算，参数文字复用`text`层，完整方向4在`all`中验收。不能把各单项差值简单相加，因为综合共享/裁剪逻辑及布局变化会改变结果。`base`仍包含所有配置共用的扇区缓存；关闭缩放时已使用固定尺寸直接路径，取消尺寸累加/重采样运算。

全开占用：LUT **28.94%**，寄存器 **19.23%**，BRAM9K **29.69%**，DSP **17.24%**，PLL **50%**。8MiB SDRAM中双帧仍占2457600字节（29.30%）；显示侧保持单源读取，约73.14MB/s平均需求，对应40MHz×32bit的160MB/s理论峰值。峰值不等于可持续实测带宽。

当前没有因器件容量超限而必须砍掉某方向的证据，全部保留供用户选择。缩放关闭约节省3 DSP；转场约2 DSP；文字层是新增LUT的主要来源。精确收益应以选定组合重新综合为准。

## 剩余板级工作

- 仍只支持SDHC扇区寻址、四张连续文件；没有完整FAT遍历、碎片链、热插拔/CRC恢复。单扇区缓存可能在纵向放大时重读源行，装载时间依图片尺寸而变。
- 25MHz像素时钟实际59.524Hz；不同显示器兼容性需要实测。
- `PHY-7002`包内SDRAM中间ECO位置告警，以及仅到`SDRAM_CLK`的`PHY-5079`本地转发时钟告警仍保留。路由检查/正WNS/数字仿真不能替代实际时钟质量验证。
- 尚无完整TF板级IO延迟模型，尚未烧写TF卡/JTAG/配置Flash，未做冷启动、HDMI音频接收和长稳实测。按 [bringup.md](bringup.md) 继续。
